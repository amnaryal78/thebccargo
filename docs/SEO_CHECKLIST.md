# SEO checklist for every new or changed page

Run `npm run build && npm run seo:check && npm test` before finishing. The checks below are enforced by `scripts/seo-check.mjs` and `tests/seo-static.test.ts`, except where marked (manual).

## Metadata
- [ ] Static page: add `{ title, description }` to `src/data/pageMeta.ts` and render it with `<Seo {...}>` from that map. Never type the text in two places (prerender and page must match).
- [ ] Title 60 characters or fewer, description 70 to 160 (test).
- [ ] No prices, transit times, licence numbers, years, counts ("190+") or "licensed/SLA" wording unless the owner confirmed it (test).
- [ ] One canonical, absolute, on `https://thebccargo.com`, no query string. `<Seo>` defaults to this; never use `window.location.origin`.
- [ ] Private or utility page (login, admin, 404, search results): `noindex` and not in the sitemap.

## Crawlability
- [ ] Add the route to `src/App.tsx`, `vercel.json` rewrites (for a new top-level path) and `scripts/generate-sitemap.mjs`.
- [ ] Page appears in the prerender (static pages come from `PAGE_META`; services from `servicesData.ts`; guides from `countryGuides/`; blog posts from Supabase at build).
- [ ] Reachable by a plain `<a href>` from at least one other prerendered page (no orphan).
- [ ] Moved or removed URL: add a 301 to `vercel.json` AND a `<Navigate>` in `App.tsx`; remove it from the sitemap (test checks the sitemap never lists a redirected URL).

## Content truthfulness
- [ ] Every claim is supported by the business. Unknown facts go in `docs/OWNER_TODO.md`, not on the page.
- [ ] No invented author, review, rating, award, price, job or article. No `aggregateRating`, `JobPosting`, `priceRange`, `geo` or `postalCode` without owner data (check fails the build).
- [ ] Business facts (name, phone, address, hours, social links) come from `src/data/business.ts` only.

## Structure
- [ ] Exactly one `<h1>` that states the page topic; logical h2/h3 (check fails on more than one).
- [ ] Descriptive link text, not "click here".
- [ ] Breadcrumb JSON-LD is generated by the prerender from the URL path; visible breadcrumbs must match it (manual).
- [ ] Every `<img>` has `alt` (empty for decorative), `width` and `height`; the first-screen image is not lazy-loaded (manual).

## Structured data
- [ ] Only types that match visible content: LocalBusiness (home only), WebSite (home), Service, Article/BlogPosting, FAQPage (only if the FAQ is visible), BreadcrumbList.
- [ ] Other pages reference the business with an inline `organizationRef`, not `@id` (Google does not resolve `@id` across pages).
- [ ] Validate new JSON-LD with Google Rich Results Test (manual, UNVERIFIED by tooling in this repo).
